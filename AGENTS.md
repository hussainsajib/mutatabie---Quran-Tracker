# AGENTS.md

Quran Tracker: self-hosted app for word-by-word hifdh/tajweed mistake marking on the printed Madinah Mushaf. FastAPI (async SQLAlchemy) + React/Vite SPA + PostgreSQL, shipped as one Docker image for Cloud Run. `README.md` holds the full feature, security, API, and deploy narrative — read it before touching auth/deploy.

## Commands

- Full stack: `docker compose up --build` → http://localhost:8080 (runs `alembic upgrade head` then uvicorn automatically).
- Backend dev (from `backend/`): `uvicorn app.main:app --reload --port 5100`. Run `alembic upgrade head` first.
- Frontend dev (from `frontend/`): `npm run dev` → http://localhost:5173; Vite proxies `/api` to :5100 so cookies stay same-origin.
- Frontend typecheck + build: `npm run build` (runs `tsc && vite build`).
- Local Postgres only: `docker compose up -d db` — user/db `quran_tracker`, password `Bismillah@6204`, matching `config.py` defaults so backend dev works with no `.env`.
- Regenerate mushaf data (from repo root): `python scripts/build_mushaf_json.py`.

Alembic must run from `backend/` (`prepend_sys_path = .`). The DB URL comes from the `DATABASE_URL` env var / `.env`, not `alembic.ini`.

## Generated files — don't hand-edit

- `frontend/public/mushaf/**` (index + 604 page JSONs) and `backend/app/data/words_meta.json` are generated by `scripts/build_mushaf_json.py` from `scripts/*.csv`. Edit the script or CSVs, then regenerate.
- `frontend/dist/` is Vite output (gitignored); the backend serves it in production.

## Architecture notes

- Single origin in prod: FastAPI serves `/api/*` plus `/assets`, `/fonts`, `/mushaf`, and an SPA fallback — but only `if DIST.exists()` (i.e. after a frontend build). In dev the backend does not serve the frontend.
- `word_id` is authoritative: the backend derives `surah`/`ayah`/`word_number`/`location` server-side from in-memory `words_meta.json` (loaded in `app/main.py` lifespan). Marks endpoints ignore client-supplied location; valid range is `1..83668` (also a DB check constraint).
- Auth = httpOnly JWT `access_token` (path `/`) + rotating refresh token (path `/api/auth`, stored as SHA-256 hash). CSRF is double-submit: state-changing requests must echo the `csrf_token` cookie in the `X-CSRF-Token` header (`frontend/src/api/client.ts` does this; `/api/auth/csrf` bootstraps the cookie).
- `DATABASE_URL` must use the asyncpg driver (`postgresql+asyncpg://`) with percent-encoded special chars (e.g. `%40` for `@`); `alembic/env.py` passes the URL straight to the engine to preserve encoding.
- `SECRET_KEY` fails fast in production if left at its default (`config.py: ensure_secret_key()`). Google OAuth returns 503 until `GOOGLE_CLIENT_ID` is set.
- Rate limiting keys on client IP; the Docker CMD passes `--proxy-headers --forwarded-allow-ips='*'` so the real client IP is seen behind Cloud Run.

## Testing / verification

- No test suite, linter, or formatter config exists for either side. The only CI is `deploy/cloudbuild.yaml` (build + deploy only, no tests).
- Verify changes with `npm run build` (frontend typecheck) and by running the stack locally.
